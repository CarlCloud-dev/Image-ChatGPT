# Image ChatGPT Linux 服务

这个服务复用桌面版浏览器驱动和队列。网页提供 ChatGPT 的 API 配置及账号管理，不提供网页任务提交。ChatGPT 并发可设置为 1–5 个环境，全局最多同时执行 5 个任务；配置会保存在服务器。每个环境使用独立对话，成功完成 30 个任务或会话满 2 小时后，在下一项任务开始前安全切换新对话。服务器内存有限，建议从 1–2 个环境开始。无需 Electron 桌面程序，Chrome 在 Xvfb 中运行。

服务通过 Docker Compose 使用 Playwright 官方运行镜像，首次启动在容器内安装 Chrome、x11vnc 和生产依赖；不在宿主机安装 Node.js。容器重建时会重新安装容器内系统软件。数据保存在 `server/data`，它包含密钥、浏览器登录资料、任务记录和生成图片，应限制文件系统权限并单独备份。

服务每次启动后，API 默认关闭。管理页面首次使用 `server/data/config/local_api.json` 中的 `api_key` 登录，并在页面设置自己的访问密码；以后使用所设密码登录。网页会话使用安全 Cookie，不把密码存储在浏览器脚本中。网页中手动开启 API 后才能提交与查询任务；程序化调用仍需使用 API 密钥，可在登录页面内复制。

## 登录

管理页面点击“打开登录浏览器”，即可在页面内完成 ChatGPT 登录或验证。远程桌面由登录会话保护，VNC、WebSocket 桥接和浏览器调试端口只监听容器内部的回环地址，不映射到服务器公网或宿主机。关闭网页中的浏览器画面不会退出浏览器。账号快照导入只接受 ChatGPT/OpenAI 域的 Cookie。

## API

所有请求使用 `Authorization: Bearer <api_key>`，接口通过 `https://img.888824.xyz` 访问。先在管理页面手动开启 API。

1. 可选：逐张调用 `POST /api/uploads`，请求体为图片原始二进制，`Content-Type` 为 `image/png`、`image/jpeg`、`image/webp` 或 `image/gif`。单张最多 20 MB。成功返回 `{"id":"...","bytes":123}`。
2. 调用 `POST /api/generate`，JSON 示例：`{"model":"chatgpt","prompt":"生成一张图片","count":1,"reference_ids":["上传返回的ID"]}`。`model` 可为 `chatgpt` 或 `gemini`，`count` 为 1–4。无参考图时可以省略 `reference_ids`。多张参考图按 ID 数组顺序一次性提交给浏览器。
3. 接口返回 202 和 `jobs` 任务 ID 数组。调用 `GET /api/jobs/{id}` 查询，成功后从返回的 `images` 路径下载结果，请求时仍需携带密钥。完成任务返回 `images_expire_at` 和 `images_expired`；生成图片完成后保留 2 小时，过期下载返回 HTTP 410。后台每分钟清理过期的服务器生成图片。

上传文件 ID 最少保留 24 小时；执行中或排队中的任务仍引用的参考图不会被过期清理。服务重启时，未完成任务标记失败，不自动继续。队列暂停后需在管理页面检查浏览器并手动恢复。

远程 API 不接受客户端电脑的本地绝对路径，避免读取服务器任意路径。原有桌面本地 API 未更改。
